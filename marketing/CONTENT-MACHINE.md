# Контент-машина Tournable

Как устроено производство контента: что делает код, что делаете вы, что делает AI и чего мы намеренно не делаем.

Вводные, под которые всё собрано:
- Каналы: Instagram, TikTok, Telegram, YouTube, Threads
- Языки: русский и казахский
- Бюджет на инструменты: 0 ₸
- Вы — лицо продукта, готовы сниматься и озвучивать
- ЦА: школы/колледжи/вузы и корпоративный спорт/HR
- Аккаунты есть, но пустые
- За вами — экспертная оценка, корректировка и публикация. Всё остальное автоматизируется

## 1. Про Higgsfield и MCP — прямой ответ

**Higgsfield MCP существует и официальный.** Сервер поднят самой Higgsfield на `https://mcp.higgsfield.ai`, работает с Claude Code, авторизация — через аккаунт Higgsfield, без ключей. Даёт доступ к 30+ моделям генерации изображений и видео (Kling, Veo, Seedream, Soul и другие), изображения до 4K, видео до 15 секунд.

**Но подключать его сейчас нет смысла, и вот почему.**

Генерации тратят кредиты вашего аккаунта Higgsfield. При бюджете 0 ₸ вы упрётесь в бесплатный лимит через несколько роликов. Это первое.

Второе важнее. Higgsfield генерирует **вымышленные кадры**: людей, которых нет, залы, которых нет, эмоции, которых не было. Ваш продукт — таблицы, сетки и расписания. Ролик, где сгенерированные дети радуются на сгенерированном стадионе, не продаёт систему учёта турниров: он не показывает продукт и при этом читается зрителем как сток. А аудитория школьных завучей и HR — не та, которая прощает синтетическую картинку.

То, что реально продаёт ваш продукт, — **запись экрана с заполненными данными и ваше лицо рядом**. Это ноль рублей и ноль генераций.

**Когда возвращаться к Higgsfield:** когда появятся первые платящие клиенты и бюджет, а контент упрётся в потолок формата «экран + лицо». Тогда генеративное видео пригодится для заставок и переходов — то есть для 3 секунд ролика, а не для всего ролика.

### Что подключать вместо него — сейчас, бесплатно

| Задача | Инструмент | Стоимость |
|---|---|---|
| Сценарии, тексты, подписи, хештеги, перевод на казахский | Claude Code (уже здесь) | входит |
| Карусели из статичных картинок | `marketing/studio` в этом репозитории | 0 |
| Демо-данные для скринов и видео | `scripts/seed-demo.mjs` | 0 |
| Запись экрана | Win + Alt + R (встроено в Windows 11) или OBS | 0 |
| Монтаж вертикальных роликов | CapCut | 0 на базовом тарифе |
| Субтитры | CapCut, автоматические, с ручной правкой казахского | 0 |
| Публикация в Telegram и Threads | `scripts/publish.mjs` | 0 |

Отдельно: **Claude в браузере** (Chrome-расширение) полезен для ресёрча конкурентов и разбора чужих аккаунтов, но постить за вас он не должен — этим занимается `publish.mjs` по официальным API.

## 2. Что уже работает в репозитории

### 2.1 Демо-данные

```bash
node scripts/seed-demo.mjs
```

Наливает два полностью заполненных турнира — это фундамент всего визуального контента. Снимать пустой продукт бессмысленно.

- **Спартакиада школ Астаны 2026** — 16 команд, 4 группы, сыгранная групповая стадия, плей-офф до финала, составы по 11 игроков, голы, ассисты, карточки, чемпионат с сезоном и публичными страницами команд и игроков.
- **Корпоративная лига Астаны 2026** — 10 команд, сыграно 6 туров из 9. Видна и таблица, и ближайшие матчи: турнир выглядит живым, а не архивным.

Данные детерминированы: повторный запуск даёт те же счета и тех же бомбардиров. Скрин, снятый через месяц, не будет противоречить ролику, снятому сегодня.

Доступ — одно из двух в `.env.local`:
```
SUPABASE_SERVICE_ROLE_KEY=...
SEED_OWNER_EMAIL=ваш@email
```
либо
```
SEED_EMAIL=ваш@email
SEED_PASSWORD=пароль
```

Первый вариант лучше: обходит RLS и лимит бесплатного плана в один турнир. Ключ лежит в Supabase → Project Settings → API.

Перезалить с нуля: `node scripts/seed-demo.mjs --reset`

Названия школ, компаний и игроков вымышленные.

### 2.2 Карусель-студия

```bash
node marketing/studio/render.mjs                 все посты
node marketing/studio/render.mjs ru-korporativ-hr   один пост
```

Читает JSON из `marketing/studio/posts/`, выдаёт в `marketing/out/<slug>/`:
- `01.png … NN.png` — слайды 1080×1350, готовые к заливке
- `caption.txt` — подпись с хештегами
- `NN.html` — исходники слайдов, если нужно что-то поправить руками

Типы слайдов: `cover`, `text`, `list`, `stat`, `screenshot`, `quote`, `cta`. Кегль заголовка подбирается по длине текста автоматически — длинная фраза не вылезет за край.

Размеры: `post` (1080×1350, лента), `story` (1080×1920, Stories и обложки Reels), `square` (1080×1080, Telegram и VK).

Слайд `screenshot` вставляет скрин продукта в рамку браузера. Если файла ещё нет, слайд собирается с заглушкой, а в консоли печатается список того, что осталось доснять.

Стиль взят из продукта: акцент `#059669` — тот же зелёный, что в теме футбола в `src/lib/sports.ts`. Лента и продукт читаются как одна система.

Готовые посты сейчас:

| Файл | Язык | ЦА | О чём |
|---|---|---|---|
| `ru-5-oshibok-spartakiada` | ru | школы | 5 мест, где спартакиада ломается |
| `kz-5-qate-spartakiada` | kz | мектептер | то же на казахском |
| `ru-turnir-za-3-minuty` | ru | школы, вузы | демонстрация продукта по шагам |
| `ru-korporativ-hr` | ru | HR | турнир, который не висит на одном человеке |

### 2.3 Банк видеосценариев

`marketing/video/scenarios.md` — 12 покадровых сценариев с хуками, титрами и текстом озвучки, привязанные к демо-данным. Там же список из 9 дублей экрана, которые снимаются один раз и переиспользуются во всех роликах.

### 2.4 Автопостинг

```bash
node scripts/publish.mjs ru-5-oshibok-spartakiada             сухой прогон
node scripts/publish.mjs ru-5-oshibok-spartakiada --publish   публикация
```

**Без `--publish` не публикует ничего** — только печатает, что и куда ушло бы. Публикация необратима, поэтому подтверждение всегда осознанное.

- **Telegram** — альбом до 10 фото одним сообщением, подпись на первом. Нужны `TELEGRAM_BOT_TOKEN` (бот из @BotFather, добавленный в канал администратором) и `TELEGRAM_CHANNEL_ID`.
- **Threads** — карусель через Graph API. Threads сам ходит за картинками по публичным ссылкам, поэтому PNG сначала заливаются в публичный бакет Supabase Storage `marketing`. Нужны `THREADS_USER_ID`, `THREADS_ACCESS_TOKEN` и `SUPABASE_SERVICE_ROLE_KEY`.

Каналов без ключей скрипт просто не касается.

**Instagram, TikTok и YouTube остаются ручными.** Не потому что лень: Instagram Graph API требует бизнес-аккаунт, привязанную страницу Facebook и одобренное разрешение `instagram_content_publish`; TikTok Content Posting API открывается только после ревью приложения, а до него посты уходят в черновики; загрузка на YouTube съедает квоту Data API непропорционально быстро. Пока аккаунты пустые, проходить ревью не за чем — вернуться к этому имеет смысл после первой сотни подписчиков.

## 3. Недельный цикл

Один продакшен-блок в неделю, остальное — публикация.

**Понедельник, блок 2–3 часа. Съёмка.**
Один раз запускается `npm run dev` на демо-данных, и снимаются все дубли экрана из списка в `scenarios.md`. Затем 6–8 дублей лица под хуки из сценариев — подряд, в одной футболке, чтобы кадры были взаимозаменяемы. Всё складывается в `marketing/footage/`.

**Вторник, 1 час. Сборка.**
Монтаж 3–4 роликов в CapCut из снятого. Субтитры автоматом, казахский правится руками — автораспознавание на нём ошибается.

**Среда, 30 минут. Карусели.**
Правится JSON в `marketing/studio/posts/`, запускается рендер. Пачка PNG и подписи готовы.

**Четверг–воскресенье. Публикация.**
Telegram и Threads — через `publish.mjs`. Instagram, TikTok, YouTube — вручную с телефона.

**Ритм:** 3 ролика и 2 карусели в неделю. Меньше — алгоритмы не разгоняются, больше — при одном человеке качество падает, а качество здесь важнее частоты, потому что ЦА взрослая.

## 4. Разделение труда

**Claude Code делает:** сценарии, тексты слайдов, подписи, хештеги, перевод на казахский, рендер каруселей, генерацию демо-данных, публикацию в Telegram и Threads, разбор метрик.

**Вы делаете:** говорите в кадр, записываете экран, монтируете, проверяете казахский, решаете что публиковать, отвечаете в комментариях.

**Ответы в комментариях не автоматизируем.** Комментарий от завуча или HR-директора — это лид. Автоответ его убивает.

## 5. Чего не делаем

- **Не генерируем людей и эмоции.** Продукт — таблицы и сетки; синтетические кадры их не продают и вызывают недоверие у взрослой ЦА.
- **Не пишем «Live».** Ни в титрах, ни в подписях, ни в обложках. Пишем «Табло». Связка «live + спорт + счёт» читается антифрод-сканерами платёжных провайдеров как профиль ставок — один отказ по этой причине уже был, разбор в `CLAUDE_CONTEXT.md`.
- **Не используем эмодзи.** Нигде: ни в титрах, ни в подписях, ни в слайдах. Вместо них — иконка, цветной блок или номер.
- **Не выдаём демо-турниры за реальные.** Названия вымышленные; если в кадре они читаются крупно, это стоит один раз проговорить.
- **Не обещаем того, чего нет в продукте.** Если фича недоступна на бесплатном плане — говорим об этом в том же ролике.
- **Не покупаем подписчиков и не участвуем в чатах активности.** Для ЦА, которую надо конвертировать в платящих, накрутка вредна: она портит охваты и не даёт лидов.

## 6. По чему считаем результат

Подписчики — не метрика. Метрики, ради которых всё это делается:

| Метрика | Где смотреть |
|---|---|
| Переходы из соцсетей | Vercel Analytics, источники переходов |
| Регистрации | `/admin/metrics`, блок привлечения |
| Созданные турниры | `/admin/metrics`, блок активации |
| Обращения в WhatsApp | вручную, по факту |
| Конверсия в платный план | `/admin/metrics`, блок денег |

На старте главная цифра — **сколько турниров создано за неделю**. Пока она не растёт, менять надо контент, а не частоту публикаций.

## 7. Что нужно от вас, чтобы машина заработала целиком

1. Добавить в `.env.local` доступ для сида — `SUPABASE_SERVICE_ROLE_KEY` и `SEED_OWNER_EMAIL`, и запустить `node scripts/seed-demo.mjs`.
2. Снять 9 дублей экрана из `scenarios.md`, сложить в `marketing/footage/`.
3. Снять 5 скринов для карусели `ru-turnir-za-3-minuty` и положить в `marketing/shots/` под именами, которые печатает рендерер.
4. Создать бота в @BotFather, добавить его администратором в канал, вписать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHANNEL_ID`.
5. Для Threads — получить `THREADS_USER_ID` и `THREADS_ACCESS_TOKEN` в Meta for Developers.
6. Оформить пустые аккаунты: аватар, шапка, описание, закреплённый пост. Это отдельная задача, её стоит сделать до первой публикации.
